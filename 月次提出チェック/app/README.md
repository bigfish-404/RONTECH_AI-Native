# app フォルダ説明書

## 1. app の役割

`app` は、月次提出チェックのプログラム、人員リスト、設定、バックアップ、テストをまとめた製品本体である。

通常の利用者は `app` 内のファイルを直接開かず、製品フォルダ直下の `月次提出チェックを起動.bat` をダブルクリックして使用する。

このツールは、毎月提出される勤務表と交通宿泊費申請書（以下「交通費申請書」）を人員リストと照合し、次の点をチェックする。

- 人員リストの全員が勤務表と交通費申請書を提出しているか。
- 勤務表の年月（A1・D1）と交通費申請書の申請年月（H4）が対象年月になっているか。
- 出勤・退勤を入力した日に、勤務場所がリストの値で入力されているか。
- 勤務表の出社日（勤務場所が「在宅」以外で入力されている日）と交通費申請書の日付が一致しているか。

問題がある人には、チャットにそのまま貼り付けられる連絡文（日本語）を作成できる。

実行には Windows PowerShell 5.1 と既定ブラウザを使用する。Excel、Node.js、Python、Webサーバーをインストールする必要はない。Excelファイルは xlsx の中身（XML）を直接読むため、Excelで開いたままのファイルもチェックできる。

## 2. 使い方

1. `月次提出チェックを起動.bat` をダブルクリックする。ブラウザにチェック画面が開く。
2. 左の「人員リスト」に、提出が必要な人をフルネームで登録する。定期券を買っている人は「定期券」にチェックを付ける。「リストを保存」を押すと確定する。
3. 上部の「対象年月」を選び、「提出フォルダ」に勤務表と交通費申請書が入っているフォルダを指定する。
4. 「チェック実行」を押す。人員リストを保存していない場合は、先に保存してからチェックする。
5. 結果表の行をクリックすると、指摘事項と日付照合のカレンダーが開く。
6. 「連絡文」を押すと連絡文が表示される。必要なら書き換えて「コピー」を押し、チャットに貼り付ける。

## 3. フォルダ構成

```text
月次提出チェック/
├─ 月次提出チェックを起動.bat
└─ app/
   ├─ backup/staff/        人員リスト保存前のバックアップ
   ├─ config/              settings.json（提出フォルダ・対象年月）
   ├─ data/staff/          人員リスト.csv
   ├─ logs/                application.log
   ├─ modules/
   │  ├─ common/           HTTP、設定保存
   │  └─ check/            Excel読取、照合ルール、画面API
   ├─ runtime/             起動とローカルサーバー
   ├─ tests/               TEMPだけを使う自動テスト
   ├─ web/
   │  ├─ shared/           画面外枠と共通処理
   │  └─ check/            チェック画面
   └─ README.md
```

このツールは注文書作成ツールと独立している。ファイル、設定、ポート（4200～4226）、認証情報を共有しない。

## 4. 人員リスト.csv

`data/staff/人員リスト.csv` は人員リストの正式な主データである。画面の「リストを保存」で更新され、保存前の内容は `backup/staff/` に日時付きで残る。ExcelでもそのままBOM付きUTF-8として開ける。

```text
氏名,定期券
徐媛媛,
山田太郎,○
```

- 氏名はフルネームで入力する。全角・半角と空白の違いは同じ名前として扱う。
- 定期券の列は「○」なら定期券あり、空欄なら定期券なしである。

## 5. チェックのルール

### ファイルの特定

- 提出フォルダの直下にある `.xlsx`・`.xlsm` を対象にする。サブフォルダは見ない。`~$` で始まるExcelの一時ファイルは無視する。
- 人員リストの氏名を起点に、その氏名を含むファイル名を探す。比較の前に、ファイル名と氏名の両方で全角・半角をそろえ、空白を取り除く。括弧の有無や種類は関係しない。
- ファイル名に「勤務表」を含むものを勤務表、「交通」を含むものを交通費申請書とする。
- 同じ人の同じ種類のファイルが複数ある場合は「注意」とし、更新日時が最も新しいファイルをチェックする。
- 人員リストのどの氏名も含まないファイルと、種類を判別できないファイルは、結果表の下に一覧表示する。

### 読み取るセル

| 帳票 | シート | 項目 | セル |
|---|---|---|---|
| 勤務表 | 勤務表 | 年・月 | A1・D1 |
| 勤務表 | 勤務表 | 氏名 | E4 |
| 勤務表 | 勤務表 | 日付・出勤・退勤・勤務場所 | 10～40行目のA・C・D・K列 |
| 勤務表 | 勤務表 | 勤務場所の選択肢 | K10のデータの入力規則（リスト）が参照するセル。テンプレートではK132～K135 |
| 交通費申請書 | 交通宿泊申請 | 申請年月・申請者 | H4・H5 |
| 交通費申請書 | 交通宿泊申請 | 日付・類型 | 9行目から「件数」行の手前までのC・H列 |

指定のシート名が見つからない場合は先頭のシートを読む。

### 出社日の判定

勤務表の各日を次のように分類する（`modules/check/CheckRules.ps1` の `Get-AttendanceCategory`）。

| 分類 | 条件 |
|---|---|
| 休み | 出勤・退勤（C・D列）も勤務場所（K列）も空欄 |
| 勤務場所未記入 | 出勤・退勤が入力されているのに勤務場所が空欄 |
| 在宅 | 勤務場所に「在宅」を含む |
| 出社 | 勤務場所が「在宅」以外で入力されている |

### 判定

| 項目 | NG | 注意 | 対象外 |
|---|---|---|---|
| 勤務表 | 未提出、読込不可 | 複数提出 | — |
| 交通費 | 未提出、読込不可 | 複数提出 | 定期券あり。出社日が0日なら提出不要（OK） |
| 勤務表の年月 | 対象年月と違う、読み取れない | — | — |
| 申請年月 | 対象年月と違う、空欄、読み取れない | — | 定期券あり |
| 勤務場所 | 出勤・退勤があるのに空欄、リストにない値 | — | — |
| 日付照合 | 出社日でない日の申請、出社日の申請漏れ、日付を読み取れない行、対象月以外の日付 | — | 定期券あり |

- 日付照合は、交通費申請書の類型が空欄または「交通費」の行だけを使う。宿泊費・会議費・他の費用の行は照合しない。
- 同じ日付の行が複数あっても1日として数える（往路・復路を別の行に書いた場合など）。
- 勤務場所未記入の日は「勤務場所」でNGとし、日付照合には含めない。
- 勤務表の年月が対象年月と違う場合は、日付照合とカレンダー表示を行わない。別の月の日付を当てはめると曜日や日付が食い違うためである。年月を直して再提出してもらってから照合する。
- 休みの日に交通費を申請している場合は、出社日ではない日の申請としてNGにする。
- 勤務場所の選択肢は、各勤務表のK10に設定されたデータの入力規則（リスト）から読む。入力規則が見つからない場合や、別シート・名前定義を参照している場合は、値のチェックを行わない。
- 「出社日数と申請日数が一致していません」の文は、日数が実際に違う場合だけ連絡文に入れる。
- 日付は日付値のほか、「9/10」「R8.9.10」「2026年9月10日」「20260910」などの文字列も読み取る。読み取れない日付、空欄の日付、対象月以外の日付は、それぞれ別のNGとして行番号とセルの内容を示す。
- 「日付照合」欄には照合できなかった行数も表示する。申請0日が「未提出」ではなく「読めない書き方」である場合に、表を開いた時点で分かるようにするためである。
- 宿泊費・会議費・他の費用の行は照合しないが、参考情報として詳細に行番号と類型を表示する。黙って除外すると、件数が合わない理由が分からなくなるためである。
- ファイル名の年月が対象年月と違う場合、書類の氏名欄が人員リストの氏名と違う場合、定期券なしの人の申請書に定期券の行がある場合は「注意」とする。

## 6. 主な処理の流れ

1. `runtime/Start.ps1` が4200～4226番ポートから空きを選び、`runtime/Server.ps1` を起動して既定ブラウザを開く。
2. 画面が `GET /api/data` で人員リスト、提出フォルダ、対象年月を読み込む。
3. 「チェック実行」で `POST /api/check` を呼ぶ。サーバーは提出フォルダのファイルを列挙し、人員ごとに勤務表と交通費申請書を読み、照合結果をJSONで返す。
4. 画面は結果表、指摘事項、カレンダー、連絡文をJSONから組み立てる。表示文言と連絡文の文面は `web/check/check-format.js` にまとめてある。

| API | 用途 |
|---|---|
| `GET /api/health` | 起動確認と同一製品判定 |
| `GET /api/data` | 人員リスト、提出フォルダ、対象年月の取得 |
| `POST /api/staff` | 人員リストの保存 |
| `POST /api/check` | 提出チェックの実行 |
| `POST /api/folder-path` | 直接入力した提出フォルダの保存 |
| `POST /api/select-folder` | フォルダ選択画面の開始 |
| `POST /api/folder-selection` | フォルダ選択結果の取得 |
| `POST /api/shutdown` | サーバーの終了 |

サーバーは `127.0.0.1` だけで待ち受け、起動ごとに発行するトークン、Host、Origin を検証する。

## 7. 各ファイルの責務

| ファイル | 機能 |
|---|---|
| `modules/common/Http.ps1` | HTTPの解析と応答、静的ファイル配信、フォルダ選択画面、ログ出力 |
| `modules/common/SettingsStore.ps1` | `settings.json` の読込と原子的な保存 |
| `modules/check/XlsxReader.ps1` | xlsx/xlsm のZIPを開き、指定シートのセル値とデータの入力規則（リスト）を読む |
| `modules/check/WorkbookParsers.ps1` | 勤務表・交通費申請書のセル位置の定義と、日付・年月の解釈 |
| `modules/check/StaffRepository.ps1` | 人員リストCSVの読込、検証、バックアップ付き保存、氏名の正規化 |
| `modules/check/SubmissionScanner.ps1` | 提出フォルダの列挙、ファイル種類の判定、ファイルと人員の対応付け |
| `modules/check/CheckRules.ps1` | 1人分の判定ルール |
| `modules/check/CheckApi.ps1` | 画面APIとチェック全体の制御 |
| `web/check/check-format.js` | 判定結果の表示文言と連絡文のテンプレート |
| `web/check/check-view.js` | 人員リスト、結果表、詳細、カレンダーの描画 |
| `web/check/check-actions.js` | 追加、削除、保存、再読込、チェック実行、フォルダ選択、コピー |

## 8. テスト

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-SmokeTests.ps1
```

テストはTEMPに架空の勤務表・交通費申請書を生成し、次を検証する。正式な人員リスト、設定、提出フォルダは変更しない。

- 全PowerShellファイルの構文とBOM、Node.jsがある環境での全JavaScriptファイルの構文
- 設定と人員リストの保存・再読込・バックアップ、氏名の重複検出
- ふりがな（rPh）を除いたセル読取、指定シートの選択、Excelで開いたままのファイルの読取
- 和暦・全角の日付文字列の解釈
- OK・NG・定期券・未提出・出社なしの各パターンの判定、リスト外ファイルの検出
- 連絡文の文面（Node.jsがある環境のみ）

## 9. 保守時のルール

- PowerShellファイルは Windows PowerShell 5.1 で日本語を正しく読むため、UTF-8 BOM付きで保存する。
- 帳票のセル位置が変わった場合は `modules/check/WorkbookParsers.ps1` を変更する。
- 判定ルールは `modules/check/CheckRules.ps1`、画面の文言と連絡文は `web/check/check-format.js` を変更する。
- 変更後は `tests/Run-SmokeTests.ps1` を実行する。
