# app フォルダ説明書

## 1. app の役割

`app` は、帳票作成ツールのプログラム、注文データ、Excelテンプレート、設定、バックアップ、テストをまとめた製品本体である。

通常の利用者は `app` 内のファイルを直接開かず、製品フォルダ直下の `帳票作成ツールを起動.bat` をダブルクリックして使用する。

このツールには、次の機能がある。

- CSVの注文主データを読み込み、会社・案件・技術者単位で一覧表示する。
- 画面上で会社、案件、技術者を追加、変更、複製、削除する。
- 画面上の全データをCSVへ保存する。
- チェックした技術者だけを対象に注文書を生成する。
- 会社ごとにExcelとPDFを作成し、利用者が指定した出力先へ保存する。
- CSV更新前の状態を自動的にバックアップする。

実行には Windows PowerShell 5.1、既定ブラウザ、Microsoft Excel デスクトップ版を使用する。Node.js、Python、別のWebサーバーをインストールする必要はない。

## 3. 各フォルダの内容と機能

### backup

CSVを保存する直前のデータを保管する。

- `backup/order/`: 注文主データのバックアップ。
- ファイル名には保存日時が付く。
- 誤操作や入力ミスがあった場合に、以前のCSVを確認・復元するために使用する。

このフォルダのファイルは注文書生成時には読み込まれない。

### config

利用者の設定を保管する。

- `settings.json`: モジュールごとの設定ファイル。
- 現在は注文書の出力先パスを保存する。

PCを変更して保存済みパスが存在しない場合、画面には以前のパスを表示するが、注文書の生成は停止し、出力先の再指定を求める。

### data

帳票作成に使用する主データを保管する。

- `data/order/注文データ.csv`: 注文書の正式な主データ。
- 「変更を保存」を押すと、画面上の全レコードがこのCSVへ保存される。
- 「再読込」を押すと、このCSVから最新データを読み直す。
- 案件の識別とシート名には「件名」を使用し、帳票の業務内容欄には別項目の「業務内容」を使用する。
- 旧形式CSVに「件名」列がない場合は、読込時だけ「業務内容」を件名へ引き継ぎ、次回保存時に新形式へ更新する。

注文書生成時はCSVを再読込せず、画面で選択されたレコードだけをJSONとして生成処理へ渡す。

### docs

開発者・保守担当者向けの資料を保管する。

- `注文書作成ツール_技術仕様書.md`: システム構成、データ処理、出力処理、API、セキュリティ、画面仕様、テスト方針の詳細。

### logs

ツールの実行記録を保管する。

- `application.log`: サーバーの起動、終了、処理結果、エラーなどを記録する。

問題調査に使用するため、障害発生時は削除せず保守担当者へ渡す。

### modules

業務処理を機能単位で分割したPowerShellモジュールを保管する。

#### modules/common

注文書以外の帳票でも再利用できる共通処理である。

| ファイル | 機能 |
|---|---|
| `Http.ps1` | HTTPリクエストの解析、JSON応答、静的ファイル配信などを行う。 |
| `SettingsStore.ps1` | `settings.json` の読込と安全な保存を行う。 |
| `OutputTransaction.ps1` | TEMP生成、ファイル検証、staging、最終公開、失敗時の後始末を一括管理する。 |

#### modules/order

注文書固有の業務処理である。

| ファイル | 機能 |
|---|---|
| `OrderApi.ps1` | 注文データの取得、保存、生成要求を画面APIへ接続する。 |
| `OrderRepository.ps1` | 注文CSVの読込、原子的な保存、保存前バックアップを行う。 |
| `OrderValidation.ps1` | 必須項目、数値、時間範囲、対象年月などを検証する。 |
| `OrderGenerator.ps1` | 選択データを会社ごとにまとめ、注文書生成全体を制御する。 |
| `OrderWorkbook.ps1` | Excelテンプレートへの転記、シート作成、Excel・PDF出力を行う。 |

### runtime

製品の起動とローカルサーバーの実行を担当する。

| ファイル | 機能 |
|---|---|
| `Start.ps1` | 空きポートを選び、二重起動を防止し、サーバーを起動して既定ブラウザを開く。 |
| `Server.ps1` | `127.0.0.1` 限定のHTTPサーバー、APIルーティング、認証、画面配信、終了処理を行う。 |

サーバーは4173～4199番ポートから空いているポートを自動的に使用する。

### templates

帳票生成に使用する正式なExcelテンプレートを保管する。

- `templates/order/注文書テンプレート_統合.xlsx`: 注文書のレイアウト、印刷設定、書式、計算式を持つ統合テンプレート。

テンプレートのシート名、セル位置、印刷範囲を変更すると生成処理へ影響するため、変更時は実際のExcel・PDF生成テストを行う。

### tests

製品の基本機能を確認する自動テストとテスト専用データを保管する。

- `Run-SmokeTests.ps1`: PowerShell/JavaScript構文、設定保存、CSV保存、バックアップ、出力トランザクション、出力先制限、選択データ生成を検証する。
- `Run-WorkbookIntegrationTests.ps1`: 単一選択、複数選択、全選択、混合契約、複数ページ、項目転記、10pt本文、改ページ、Excel/PDF配置を実際の帳票生成で検証する。
- `tests/fixtures/order/minimal.csv`: テスト専用の最小注文データ。

テストはシステムのTEMPフォルダだけを使用し、正式なCSV、設定、テンプレート、出力先を変更しない。

テスト実行例:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-SmokeTests.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-WorkbookIntegrationTests.ps1
```

### web

ブラウザに表示する画面を保管する。

#### web/shared

帳票画面で共通利用する外枠と基本処理である。

| ファイル | 機能 |
|---|---|
| `base.css` | 色、フォント、ボタン、入力欄、フォーカス表示などの共通デザインを定義する。 |
| `core.js` | 画面状態、共通計算、API通信、選択状態などを管理する。 |
| `shell.js` | 共通画面から注文書画面を読み込み、必要なCSSとJavaScriptを組み立てる。 |

#### web/order

注文書一覧画面固有の表示と操作である。

| ファイル | 機能 |
|---|---|
| `order.html` | 注文書画面のHTML構造を定義する。 |
| `order.css` | 会社・案件・技術者の階層、余白、線、選択色、折りたたみ表示を定義する。 |
| `order-view.js` | 会社、案件、技術者の一覧を画面へ描画する。 |
| `order-actions.js` | 追加、複製、削除、保存、再読込、生成、出力先選択を処理する。 |
| `order-validation.js` | 画面入力の検証と、エラー箇所への移動・フォーカスを行う。 |
| `order.js` | 各ボタンと入力欄へイベントを接続し、初期データを読み込む。 |

一覧は「会社 → 案件 → 技術者」の順に右へ字下げする。会社内の各案件は、四辺の枠線と角丸を持つ独立した区画として表示し、案件間に小さな間隔を設ける。

### README.md

この文書である。`app` の目的、構成、各フォルダとファイルの責務を説明する。

## 4. 主な処理の流れ

### 起動

1. 利用者が製品フォルダ直下の `帳票作成ツールを起動.bat` をダブルクリックする。
2. `runtime/Start.ps1` が空きポートを選ぶ。
3. `runtime/Server.ps1` がローカルサーバーを開始する。
4. 既定ブラウザで注文書画面を開く。
5. `data/order/注文データ.csv` を読み込み、会社は折りたたんだ状態で表示する。

出力先のフォルダボタンを押すと、フォルダ選択画面をブラウザより前に表示する。選択中は重複保存・重複生成を防ぐため画面操作を一時的に無効にし、選択画面を閉じると復帰する。

### データ保存

1. 画面上の全レコードを検証する。
2. 現在のCSVを `backup/order/` へ保存する。
3. 新しいCSVを一時ファイルへ書き込む。
4. 同一フォルダ内で正式なCSVへ置き換える。

主CSVとバックアップCSVは、Excelから直接開いても日本語が文字化けしないUTF-8 BOM形式で保存する。
すべての会社・案件・技術者を削除した0件の状態も保存でき、「会社を追加」から新しく登録できる。

### 注文書生成

1. 利用者が1名以上の技術者を選択する。
2. 「注文書を作成」を押す。
3. 選択人数、対象年月、出力先を確認する。
4. 画面上の全データを主CSVへ保存する。
5. 選択レコードだけを生成処理へ渡す。
6. 「件名」で案件をまとめてシート名と帳票上部の件名へ設定し、別入力の「業務内容」を帳票の業務内容欄へ設定する。
7. システムTEMPでExcelとPDFを生成・検証する。
8. 指定した出力先のstaging領域へコピーして再検証する。
9. 完成フォルダとして公開する。

既存の同月フォルダは上書きせず、`2026年10月（2）` のように連番を付ける。製品フォルダとその配下は出力先に指定できない。

会社ごとの成果物は次の位置へ保存する。Excelは会社フォルダ直下、PDFはPDFと同名の専用フォルダ内に置く。

```text
<出力先>/<対象年月>/<会社の保存先>/
├─ <帳票名>.xlsx
└─ <帳票名>/
   └─ <帳票名>.pdf
```

複数ページになる場合、帳票上部の表頭は2ページ目以降へ繰り返さない。時間精算は4行、固定契約は2行を1技術者のブロックとして扱い、ブロックの途中では改ページしない。帳票本文の通常文字は游ゴシック10ptとし、表題・合計などの強調表示はテンプレートの書式を維持する。

## 5. 保守時のルール

- 主データを変更する場合は `data/order/注文データ.csv` を対象とする。
- 画面デザインは `web/shared/` と `web/order/` で変更する。
- 注文書の業務処理は `modules/order/` で変更する。
- 共通サーバー、設定、出力処理は `runtime/` と `modules/common/` で変更する。
- Excel帳票のレイアウトは `templates/order/` で変更する。
- PowerShellファイルは Windows PowerShell 5.1 で日本語を正しく読むため、UTF-8 BOM付きで保存する。
- 変更後は `tests/Run-SmokeTests.ps1` と `tests/Run-WorkbookIntegrationTests.ps1` を実行する。
- 生成したExcel・PDFや一時ファイルを `app` 内へ保存しない。

将来、発注書機能を追加する場合は、`modules/purchase/`、`web/purchase/`、`data/purchase/`、`templates/purchase/` を追加し、注文書機能と主データ・設定・生成処理を分離する。
