# 帳票作成ツール 技術仕様書

## 1. 製品構成

配布フォルダ直下は、利用者が触る項目を2つに限定する。

```text
帳票作成ツール/
├─ 帳票作成ツールを起動.bat
└─ app/
```

`帳票作成ツールを起動.bat` をダブルクリックすると、空いているローカルポートを自動選択し、注文書画面を既定ブラウザで開く。

注文書の作成には Windows PowerShell 5.1、既定ブラウザ、Microsoft Excel デスクトップ版を使用する。Node.js、Python、Webサーバー製品の追加インストールは不要である。

## 2. app 配下

```text
app/
├─ runtime/                 起動とHTTPサーバー
├─ modules/
│  ├─ common/               設定、HTTP、出力トランザクション
│  └─ order/                注文書の読込、検証、生成
├─ web/
│  ├─ shared/               画面外枠と共通処理
│  └─ order/                注文書画面
├─ data/order/              注文書の主データCSV
├─ templates/order/         注文書テンプレート
├─ backup/order/            CSV更新前バックアップ
├─ config/settings.json     モジュール別設定
├─ logs/application.log     実行ログ
├─ docs/                    技術資料
└─ tests/                   TEMPだけを使うスモークテスト
```

将来、発注書を追加するときは `modules/purchase/`、`web/purchase/`、`data/purchase/`、`templates/purchase/` を追加する。注文書と発注書は画面外枠だけを共有し、主データ、検証、テンプレート、生成処理、出力先設定を分離する。未実装の画面や空モジュールは先に作らない。

## 3. データの責務

`data/order/注文データ.csv` は注文書の主データである。

- 「変更を保存」は画面上の全レコードをCSVへ保存する。
- 保存前のCSVは `backup/order/` に日時付きで退避する。
- 保存は同一ディレクトリ内の一時ファイルを使って原子的に置き換える。
- 「注文書を作成」は、最初に全レコードをCSVへ保存し、その後、チェックした技術者だけをJSONで生成処理へ渡す。
- 生成処理はCSVを再読込しない。
- 会社または案件のチェックボックスは、その配下の技術者をまとめて選択する。

## 4. 出力先

注文書の出力先は `config/settings.json` の `modules.order.outputPath` に保存する。

- 画面上部の固定操作行で、絶対パスを直接入力するか、右端のフォルダボタンから選択する。
- 絶対パスだけを受け付ける。
- 存在しない、書込みできない、または製品フォルダとその配下のパスは生成時に拒否する。
- ツールを別のPCへ移動して保存済みパスが無効になった場合、画面にパスを表示したまま生成を止め、利用者に再選択させる。
- 成果物は製品フォルダ内へ出力しない。

## 5. 全有または全無の生成

複数会社を一度に選択した場合も1ジョブとして扱う。

1. `%TEMP%\RontechDocumentTool\<job-id>` でExcelとPDFを生成する。
2. 選択会社数とExcel/PDF数が一致し、全ファイルが空でないことを検証する。
3. 出力先ドライブの `.rontech-staging\<job-id>` へコピーする。
4. 同じ検証を再実行する。
5. 同一ドライブ内で最終フォルダ名へ変更して公開する。
6. 失敗時はTEMPとstagingを削除し、最終出力を残さない。

既存の同月フォルダは上書きせず、`2026年10月（2）` のように連番を付ける。

## 6. サーバー

- 接続先は `127.0.0.1` のみ。
- 使用ポートは4173～4199から空きを自動選択する。
- 同じ製品が既に起動中なら、その画面を開いて二重起動しない。
- 起動ごとにランダムなトークンを発行する。
- APIはHost、Origin、トークンを検証する。
- 静的ファイルは `web` 配下のHTML、JavaScript、CSSだけを公開し、パストラバーサルを拒否する。
- エラー応答は `code`、`stage`、`message` を返す。

## 7. 主なAPI

| API | 用途 |
|---|---|
| `GET /api/health` | 起動確認と同一製品判定 |
| `GET /api/data` | 主データと保存済み出力先の取得 |
| `POST /api/save` | 画面上の全データを主CSVへ保存 |
| `POST /api/generate` | 選択レコードだけを生成 |
| `POST /api/output-path` | 直接入力した出力先を検証して設定へ保存 |
| `POST /api/select-output-folder` | フォルダ選択を開始 |
| `POST /api/output-folder-selection` | 選択結果を取得して設定へ保存 |
| `POST /api/shutdown` | サーバーを終了 |

## 8. 画面仕様

- 初回起動時は会社を折りたたんで表示する。
- 「再読込」では現在の折りたたみ状態を維持する。
- 「すべて折りたたむ」「すべて展開する」は一覧操作行に置く。
- 一覧操作はアイコンと文字を組み合わせた一列のツールバーにし、表示件数は置かない。
- 会社ごとに小さな間隔と角丸を付け、会社内の案件階層線は技術者表まで連続させる。
- 会社行の操作順は「案件を追加」「会社を削除」。
- 案件行の操作順は「複製」「技術者を追加」「技術者を削除」。
- 選択行は背景色を変える。
- 注文書作成前の確認画面に選択人数、対象年月、出力先を表示する。

## 9. テスト

`tests/Run-SmokeTests.ps1` は次を検証する。

- 全PowerShellファイルの構文
- Node.jsがある環境での全JavaScriptファイルの構文
- 設定ファイルの保存と再読込
- CSVの読込、原子保存、バックアップ
- 出力トランザクションの成功、検証失敗、後始末
- 製品フォルダを出力先にできないこと
- 生成リクエストで指定した出力先の使用と保存

テストデータと出力はすべてシステムTEMPに作成し、正式な主データ、設定、出力先を変更しない。
